# SutraZen《小貓的山海旅程》：沉浸式遊戲介面改版

此文件可直接交給 Codex 執行。依據 2026-11-22 對 https://sutra-zen.github.io/game/ 的桌面實際試玩，以及當時儲存庫版本 `7e39f04a383ab98d3b747365ea3e513ad7140a0e` 的原始碼檢視。開始工作時請以工作區最新版本為準，保留之後已合併的修正。

## 任務與範圍

請直接在現有專案實作這輪改版，完成可供試玩的成果與驗證，不只提出計畫。

遊戲名稱先採 **《小貓的山海旅程》**；SutraZen 作為品牌，副標為「佛法繪本探索遊戲」。核心體驗是：標題畫面 → 沉浸式大地圖 → 目前關卡 → 閱讀繪本 → 地景與城池回饋 → 下一站。

主要對象包含不熟悉遊戲的長輩。玩家只要能點「開始／繼續」、下一頁及「完成這本」，就能走完整段旅程；地圖探索是樂趣，不應成為閱讀障礙。

正式遊戲入口維持 `/game/`。保留原網站首頁、原心智圖、十四本公開閱讀器的網址與自由閱讀功能。保留既有繪本內容、原經、閱讀頁碼接續與合法完成紀錄。

本次規格更新先前設計中兩項已過時的限制：

- 遊戲內改為依序開放，書架只供複習已完成的書；舊版「遊戲自由選讀」不再是玩家入口。
- 現在已有十四本整合，請完整保留；不要退回早期只做三本的原型。

先讀取適用的 AGENTS.md、專案說明及交接文件，再檢查最新架構。若舊文件仍寫遊戲自由選讀或三本原型，以上述最新使用者需求更新相關說明。沿用現有技術與共用資料，不為這次介面改版全面重寫繪本閱讀器，也不增加登入、後端、戰鬥或付費系統。

## 目前已重現的問題

1. `/game/` 直接進入網站式頁首與地圖，沒有獨立標題畫面。
2. 「依序旅程」模式下，只完成四聖諦仍可從薄霧中的四禪開啟閱讀；返回後主按鈕改成繼續四禪。
3. 書架可開尚未完成的六處，而且閱讀返回舊書架，遊戲返回脈絡不一致。
4. 城池尚未取得的守門人彈窗仍提供「重新閱讀」未完成繪本的入口。
5. 放大地圖後仍在一般網頁的捲動容器中，上方頁首占用大量空間。
6. 目前主線提示主要是外框／光暈，缺少明確的「新關卡」文字。
7. 城池守門者縮排標牌可能只顯示「念」，需要依本次要求統一。

已經能運作的功能應保留：四聖諦共 29 頁；讀到第 3 頁離開後可續讀；到末頁按「完成這本」才增加已讀本數；完成後已有地景／城池回饋與下一本提示；重新整理後已完成紀錄仍保留。

## 一、標題畫面

使用隨本次任務附上的金棕色貓咪背景：`CC1A7C32-0620-4DB2-BCD2-A9457A83C259.jpeg`。請把附件納入專案自己的資產路徑，不使用聊天暫存路徑或外部臨時網址。若工作區未收到附件，先尋找同名提供檔；不要自行換成別的插圖。

- 滿版背景，依橫式／直式合理裁切，保持原比例。
- 疊加有足夠對比的紙感標題區，主標「小貓的山海旅程」、小品牌「SutraZen」、副標「佛法繪本探索遊戲」。文字使用網頁文字，不烘焙進圖片。
- 新玩家主按鈕「開始旅程」；有進度者「繼續旅程」。設定為次要入口。
- 主角維持既有橘色虎斑、金色衣袍小貓；背景的其他貓是裝飾，不新增選角系統。
- 點主按鈕進入地圖。從閱讀器或城池返回時，直接回遊戲內容，不反覆重播標題畫面。
- 標題畫面不放網站導覽列、長篇說明、整張書籍目錄或顯眼的清除進度按鈕。

## 二、共用遊戲介面

地圖、城池與書架使用一致的遊戲介面。可採 `/game/#map`、`/game/#city`、`/game/#shelf` 等靜態主機可用的路由，或在現有架構實作等效方案；返回與重新整理都必須正確。留意現有 `<base>` 對相對網址及 hash 的影響。

- 遊戲內容占滿可用視窗；以 CSS 滿版作為基本體驗，處理動態視窗高度與裝置安全區。
- 地圖與城池不再有網站式大標題、介紹段落、大片白邊、一般頁尾或外層頁面捲動。
- 固定底部主選單依序為 **地圖／城池／書架**，圖示搭配文字，有清楚選中狀態。
- 上方只保留精簡的旅程進度與設定入口；主要閱讀按鈕靠近拇指容易點到的位置。
- 心智圖、原網站、存檔備份與相關說明移至設定或次級選單。
- 原生瀏覽器全螢幕為選用功能；未支援或使用者退出時，CSS 滿版仍可正常玩。
- 閱讀器繼續以圖片、上方口白、下方原經為核心；不在閱讀畫面硬塞底部主選單遮住原經。

## 三、大地圖鏡頭與操作

保留現在的 16:9 世界、主陸地、群島、道路半島與五欄縱向對應。本次主要改操作與呈現，不重新安排已確認的法義地景。

- 初次進地圖，鏡頭定位右下的四聖諦法輪遺跡，縮放到名稱與目標清楚可點。
- 一根手指拖曳、兩指縮放；桌面滑鼠拖曳，另提供「＋／－」。
- 常駐「目前關卡」與「全圖」操作。使用者隨時可以找回進度，不必記住地理位置。
- 提供簡短的一次性教學：「拖曳探索地圖，點新關卡開始」。不使用長篇教學視窗。
- 鏡頭限制在合理地圖邊界，保留可探索的範圍；避免拖到整片空白或縮到標牌完全不可讀。
- 地圖背景、霧、地標、關卡標記、互通線與可點範圍必須共用同一世界座標和鏡頭轉換，放大後不能漂移。
- 標牌文字與觸控範圍不可跟著縮到極小。全圖時可減少標牌、顯示區域名，點區域再放大；不要靠重疊的小字顯示所有資訊。
- 拖曳與點擊要區分；拖曳或雙指縮放結束不可誤開繪本。處理 pointer cancellation。
- 只在地圖區處理地圖手勢；彈窗、書架與文字面板仍能正常捲動。
- 切到書架／城池再返回，保留上次地圖鏡頭；完成一本並選「前往下一站」才主動定位下一關。
- 切換橫直向後維持合理的位置與比例。手機直式也能玩，不強迫旋轉才能開始。
- 互通連線預設關閉，放在次級工具選單；閱讀順序與心智圖互通關係沿用現有資料，不混為同一種線。

現有地理配置要保留：北排七覺支、近岸排五根五力；正精進／正語／正業／正命為同組橋；喜／息／定／捨為同節點群；下方為八正道公路，右側「道諦-八正道驛站」使用馬車。

所有遊戲入口使用同一份資料及共同資格判定，包含地圖、主按鈕、路線列表、書架、城池、閱讀器返回、舊 collection 入口與完成紀錄寫入。不要只把鎖頭畫出來或只停用某個按鈕。

每本使用清楚的狀態：

| 狀態 | 地圖呈現 | 可執行操作 |
| --- | --- | --- |
| 未開放 | 薄霧／鎖頭 | 看提示、前往目前關卡；不能開始此書 |
| 目前可開始 | 清楚的「新關卡」標記 | 開始閱讀 |
| 目前閱讀中 | 「閱讀中」與頁碼／進度 | 繼續合法關卡 |

- 在尚未完成的書裡，只開放依序第一本尚未完成者。
- 初始只有四聖諦可開始。
- 「新關卡」只標在該書的一個主地標，使用持續可讀的文字與緩慢光暈；不要同一本的多個地景一起閃。
- 閱讀中改為「閱讀中」；已讀顯示完成狀態。
- 一本書有多個地景時共用同一個 book ID 和完成紀錄。例如四不壞淨／六念、四念處／四顛倒、八正道／十善業道不可變成兩關或重複加分。
- 四向四果與十結在前十三本完成後揭曉；未揭曉時，書架與路線清單也不能先洩漏名稱或提供入口。歷史已完成者仍可複習。
- 遊戲介面移除「自由選讀」與「一鍵全開」捷徑。舊展示／審稿預覽與玩家介面分離；預覽不得寫入正式紀錄。
- 一般原站閱讀器仍自由閱讀。沒有遊戲 collection 模式的正常原網址，不應套用遊戲關卡鎖，也不得寫入遊戲完成紀錄。
- 所有可寫入同一份遊戲存檔的舊 collection 入口必須遵守相同資格規則。`collectionReturn=game` 只代表返回目的地，不能視為已通過資格檢查。
- 這是本機單人遊戲的狀態一致性，不需要加帳號、伺服器驗證或防作弊工程。

## 五、存檔與舊進度相容

保留 `sutrazen.play.collection.v1` 內既有合法的 `completed`、`positions` 與 `activeBook`；若最新架構已更新 key，依現況提供相容遷移。

- 歷史已完成紀錄全部繼續有效，即使以前自由閱讀造成非依序完成，也不追溯取消。
- 未完成書籍的書籤只代表讀到哪裡，不代表關卡資格。先判定資格，再決定是否使用該書籤。
- 舊版留下的四禪／六處等未解鎖書籤要保留，但不可讓它變成目前關卡或主按鈕目標；待正式解鎖時再用來續讀。
- 複習某本已讀書，不應把主線的「繼續旅程」改指那本書。區分主線目前進度與複習返回位置。
- 完成紀錄寫入需再判定資格，且重複點擊或重新整理只計算一次。
- 保留現有備份／匯入功能，移至設定；不要在一般頁面提供顯眼的清除進度。
- 存檔失敗時顯示可理解的提醒並保留當次可用狀態，不假裝已永久存妥。設定中清楚說明進度目前保存在此裝置的瀏覽器。

## 六、書架只供複習

- 書架只提供已完成書籍的閱讀按鈕。
- 尚無已完成書時，顯示簡短空狀態與「前往第一站」。
- 如果保留未讀書的視覺空位，使用不可點的書影或問號；不要放「開始閱讀」「閱讀並收集」或可繞過主線的連結。
- 未完成但正在讀的書，回地圖用「繼續閱讀」處理，不在書架另開新入口。
- 從書架複習返回書架；複習完成不增加本數、不重播新地景獎勵、不改寫主線下一關。

## 七、閱讀與完成回饋

- 保留現有繪本圖像、口白、原經、逐頁操作與頁碼接續。不要為了新介面複製十四份閱讀器或改寫經文。
- 一直按下一頁，到末頁按「完成這本」即可過關；不新增考試、計時、分數門檻或閱讀時間門檻。
- 從遊戲開啟讀本時，保留遊戲返回脈絡；中途離開、重新整理與返回皆能回到正確的地圖／書架狀態。
- 只有合法完成才更新地景、城池與已讀本數；開啟一本、查看預覽或讀到一半都不算完成。
- 完成後在一個回饋面板中展示「讀完了」「本次亮起的地景／城池部分」及已讀本數，避免連續多層彈窗。
- 主按鈕「前往下一站」回地圖並定位下一個新關卡；次要按鈕「看看城池」。不要按下後立刻跳進下一本，讓玩家看見地圖變化。
- 畫面可短暫顯示小貓抵達／新地景亮起；以可略過的簡短回饋為限。
- 同一本在世界地圖和城池若有不同獎勵名稱，文案標明是「地圖」或「城池」的變化，避免四聖諦法輪遺跡與法輪碼頭混淆。
- 十四本完成後可觀看現有故事結尾並自由複習。完成本數是閱讀進度，不顯示「證得聖果」「已解脫」等修證認證。

## 八、城池整合

- 底部「城池」一直存在；尚未建起時能看見柔和的城池預覽與下一個建造提示，避免空白頁。
- 大地圖的三十七道品海陸港口附近，增加一個小型城池地標入口。先重用現有城池圖的縮圖／同色系圖示作為網頁疊加地標，日後可再精修底圖。
- 兩個入口打開同一座城池、讀取同一份進度。城池不算第十五本，不需要另設通關。
- 沿用既有城池解鎖規則，這輪不要重新定義城門、國王或止觀的經典對應。
- 拿燈籠的小貓標牌固定為 **「念-守門人」**，寬版、窄版、彈窗標題都一致；必要時換行，不縮成只剩「念」。標牌引線／錨點指向拿燈籠的小貓。
- 保留既有「如實消息・涅槃」指向止觀使者所呈卷軸的設計，不把它移到鼻門或當成一座涅槃建築。
- 城池區塊說明可展示相關讀本，但只有已完成的可複習；尚未解鎖的只能提示先前往目前關卡。
- 審稿預覽按鈕移出一般玩家畫面；保留開發檢視能力，但與正式進度明確分離。

## 九、視覺、易用性與載入

- 接續現有暖金色、深綠、海藍、木牌與紙卷的繪本世界；按鈕及選單有清楚層次，避免整頁變成白底網站卡片。
- 主要可點區建議至少 48 × 48 CSS px；圖示加文字，長輩不需要猜圖示。
- 「新關卡」採約 2–3 秒一循環的緩慢光暈，文字保持可讀；支援 `prefers-reduced-motion`，減少動畫時仍靠文字和符號引導。
- 保留鍵盤操作、可見焦點；彈窗可關閉，關閉後焦點返回來源。圖像不做唯一的狀態訊號。
- 處理瀏海／底部手勢區，底部選單與閱讀原經不能被遮住。
- 先載入標題和目前必要資產，不在開場下載十四本全部頁面；地圖與讀本有簡潔載入提示及失敗重試，沒有真實進度資料時不顯示假的百分比。
- 已顯示的地圖不要因資料更新整張重載或鏡頭跳回原點。
- UI 文案集中管理，先提供繁中；新標題、按鈕、狀態文字及提示採可翻譯的 key。這輪不必翻譯整套經文與十四本內容。

## 十、建議檢查的現有程式入口

以下依稽核時版本列出；先核對最新程式，不要盲目依行號修改：

- `play/worldmap-v4/worldmap.js`：`unlocked()` 把 `inProgress` 視為可進入；`primaryReader()` 優先任意 activeBook；`inspect()` 與 `openReader()` 缺少統一資格限制。
- `play/route/selectors.js`：檢查可閱讀資格及主線狀態的共用計算。
- `play/visual-v2/shelf.js`：目前所有書籍入口均可開啟，需改為只複習已完成者。
- `play/city/city.js`：城池彈窗閱讀與主按鈕也要使用相同規則。
- `play/collection/reader-bridge.js`、`play/collection/store.js`：讀本進入、書籤恢復及完成寫入都需要共同判定；保留普通原站讀本不啟用 collection 的邊界。
- `play/visual-v2/city-tactics.js`：核對守門人寬版／緊湊版名稱及錨點。
- `play/worldmap-v4/worldmap.css`：目前放大主要是固定寬圖加 overflow 容器，需升級為可用的地圖鏡頭與輸入處理。
- `scripts/build-game-entry.py`：`/game/index.html` 由既有 worldmap shell 產生並帶 `<base>`。請一起調整來源、產生器及檢查；不要只改產出 HTML，導致下次產生時覆蓋。

實作可建立共用的 `canStartGameBook`、`canReviewGameBook`、`canCompleteGameBook` 等 helper，命名依現有架構。避免把規則複製到每一頁。

注意：目前 reader bridge 遇到任何 `journey` query parameter 會直接退出，用來避免舊模式衝突。不要直接新增 `?journey=game` 當遊戲脈絡，除非已明確處理並驗證舊整合。

## 十一、具體驗收

至少針對以下風險完成必要驗證，結果如實回報：

1. 新存檔打開 `/game/` → 看見指定貓咪標題 → 開始 → 四聖諦處於清楚可點的鏡頭位置，顯示「新關卡」。
2. 此時從地圖、路線、書架、城池及舊 collection 入口都不能開始／完成未解鎖的四禪；一般原網站讀本仍可正常自由閱讀。
3. 四聖諦讀到中段返回，再續讀會回原頁；此時不增加完成本數。
4. 四聖諦末頁完成後只增加一次，地景回饋正確；「前往下一站」定位五陰，新關卡標記只有一個。
5. 書架此時只有四聖諦可複習，六處沒有可開啟的遊戲閱讀按鈕。複習四聖諦後主線仍是五陰。
6. 載入舊存檔：四聖諦已完成、四禪有書籤但未完成。四禪書籤保留，主線仍為五陰，四禪不能因書籤變成已解鎖。
7. 載入歷史非依序完成紀錄，保留那些 completed IDs，主線選第一本尚未完成者，已完成的仍可複習。
8. 前十三本完成後才揭曉第十四本；全部完成可進故事結尾，不重複計數。
9. 一書多地景同步顯現；四正勤花園仍與八正道／十善業道的完成紀錄分開。
10. 城池兩個入口一致，窄螢幕也完整顯示「念-守門人」，錨點確實位在燈籠小貓；涅槃消息仍指卷軸。
11. 地圖拖曳／縮放後標記不漂移、不誤點；返回保留鏡頭；全圖與目前關卡可把玩家帶回可用位置。
12. 以桌面、平板 4:3、手機橫式約 2:1、手機直式尺寸檢查版面；底部選單與讀本原經未遭遮擋。
13. 載入失敗、存檔不可用、減少動畫偏好及彈窗關閉都有合理結果。
14. 既有原網站首頁、心智圖與公開讀本網址可用；`/game/` 來源與產出同步。執行專案要求的檢查，若保留現有產生器則包含 `python3 scripts/build-game-entry.py --check`。
